# Key-Value Pairs

A list finds things by position. A **key-value pair** finds things by name, like a real dictionary where you look up a word to get its definition.

You might store *name* mapped to "Alice" and *age* mapped to 30. Need Alice's age? Ask for the value behind the *age* key. No counting through positions, no guessing: you go straight to what you need.

## Quiz

**1. How does a key-value pair find a value?**

- A) By its position in a line, like first or third
- B) By a name (the key) that points to the value
- C) By the size of the value in memory
- D) By the order you typed it into the program

<details>
<summary>Answer</summary>

- B) By a name (the key) that points to the value

Key-value pairs use a name, the key, to look up a value. This is the opposite of a list, which finds things by counting positions.

</details>

**2. If you stored name as "Alice" and age as 30, how would you get Alice's age?**

- A) Count through the positions until you reach the second one
- B) Ask for the value behind the age key
- C) Add name and age together
- D) Guess a number and check if it matches

<details>
<summary>Answer</summary>

- B) Ask for the value behind the age key

Because age is the key that points to 30, you just ask for the value behind age. There is no counting or guessing involved.

</details>

**3. Which everyday object works most like a key-value pair?**

- A) A stack of numbered tickets
- B) A line of people waiting in order
- C) A dictionary where you look up a word to get its definition
- D) A clock that counts seconds in order

<details>
<summary>Answer</summary>

- C) A dictionary where you look up a word to get its definition

A dictionary maps each word (key) to its definition (value), which is exactly how key-value pairs work. You jump directly to the definition without reading the whole book.

</details>
