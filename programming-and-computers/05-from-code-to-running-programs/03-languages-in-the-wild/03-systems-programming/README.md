# Systems Programming

Operating systems, game engines, and performance-critical software need languages that run close to the hardware. **C**, **Rust**, and **Go** are built for this.

These languages give the programmer fine control over memory and CPU resources: the kind of control that higher-level languages deliberately hide. The tradeoff is more complexity, but the result is software that runs as fast as the hardware allows.

## True or False

**1. True or false:** Systems programming languages like C and Rust give programmers fine control over memory and CPU resources.

<details>
<summary>Answer</summary>

**True**: Systems languages are designed for software that runs close to the hardware. They let the programmer control memory and CPU resources directly, which is what makes them suitable for operating systems and game engines.

</details>

**2. True or false:** Systems programming languages are easier to use than higher-level languages.

<details>
<summary>Answer</summary>

**False**: The tradeoff of systems languages is more complexity. They give you more control over the hardware, but that control comes with additional difficulty. Higher-level languages deliberately hide this complexity to be easier to use.

</details>

**3. True or false:** Operating systems and game engines need systems languages because performance matters most for that kind of software.

<details>
<summary>Answer</summary>

**True**: Operating systems, game engines, and performance-critical software must run as fast as the hardware allows. Systems languages like C, Rust, and Go are built for exactly this purpose.

</details>
