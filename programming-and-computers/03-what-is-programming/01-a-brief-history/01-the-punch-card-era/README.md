# The Punch Card Era

The earliest programmers never typed a single line of code. Instead, they **punched holes** into stiff paper cards, each pattern of holes representing one instruction.

To run a program, you stacked hundreds of these cards in the correct order and fed them into a room-sized machine. Then you waited, sometimes hours, for the result to print out.

> [!info] One misplaced card meant starting the whole stack over. Debugging was literally re-sorting paper.

## True or False

**1. True or false:** A single misplaced punch card could require the programmer to start the entire job over.

<details>
<summary>Answer</summary>

**True**: Punch cards had to be in the correct order with the correct hole patterns. A misplaced or incorrect card meant the whole stack had to be corrected and re-fed into the machine.

</details>

**2. True or false:** Punch card programmers could see their results instantly on a screen.

<details>
<summary>Answer</summary>

**False**: There were no screens in the punch card era. Programmers fed stacks of cards into room-sized machines and waited hours for results.

</details>

**3. True or false:** Each hole pattern on a punch card represented one instruction for the computer.

<details>
<summary>Answer</summary>

**True**: Programmers encoded instructions by punching specific patterns of holes into cards. Each pattern corresponded to a particular instruction the machine could execute.

</details>
