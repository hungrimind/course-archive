# Early Terminals

Punch cards were slow: you had to wait for an entire stack to process before seeing any result. **Terminals** changed everything.

A terminal was a screen with a keyboard connected to the computer. You typed a command, pressed enter, and saw the response *right away*. For the first time, programming became a conversation with the machine instead of a batch job you dropped off and picked up later.

## True or False

**1. True or false:** With a terminal, programmers could type a command and see the response right away.

<details>
<summary>Answer</summary>

**True**: Terminals introduced real-time interaction. You typed a command, pressed enter, and saw the response immediately, turning programming into a conversation with the machine.

</details>

**2. True or false:** Punch cards gave instant feedback, just like modern terminals do.

<details>
<summary>Answer</summary>

**False**: Punch cards were a batch process: you prepared an entire stack, submitted it, and waited for the results. There was no instant feedback. Terminals changed this by allowing immediate, interactive responses.

</details>

**3. True or false:** A terminal was a screen with a keyboard connected to the computer.

<details>
<summary>Answer</summary>

**True**: A terminal consisted of a display screen and a keyboard, giving the programmer a direct connection to the computer for interactive, real-time use.

</details>
