# Breaking Problems Down

**Decomposition** means splitting a big problem into smaller, manageable pieces. Instead of "build an app," you think: show a screen, handle a tap, save the data.

No programmer solves a huge problem all at once. You solve small problems one at a time, and together they add up to the big solution.

## Quiz

**1. What is decomposition in programming?**

- A) Deleting old code that no longer works
- B) Splitting a big problem into smaller, manageable pieces
- C) Combining many features into one big function
- D) Throwing away a failed project and starting over

<details>
<summary>Answer</summary>

- B) Splitting a big problem into smaller, manageable pieces

Decomposition means breaking a large problem into smaller parts you can handle one at a time, which together solve the whole problem.

</details>

**2. How do experienced programmers tackle huge problems?**

- A) They solve the whole thing in one big step
- B) They wait until they know the full solution before writing anything
- C) They solve small pieces one at a time that add up to the big solution
- D) They copy another program that already exists

<details>
<summary>Answer</summary>

- C) They solve small pieces one at a time that add up to the big solution

No programmer solves a huge problem all at once. The skill is breaking it into small problems and solving them one by one.

</details>

**3. Which is an example of decomposing 'build an app'?**

- A) Launch the app store listing
- B) Show a screen, handle a tap, save the data
- C) Hire a team of developers
- D) Write the entire app in one file

<details>
<summary>Answer</summary>

- B) Show a screen, handle a tap, save the data

Breaking 'build an app' into concrete steps like showing a screen, handling a tap, and saving data is exactly what decomposition looks like.

</details>
