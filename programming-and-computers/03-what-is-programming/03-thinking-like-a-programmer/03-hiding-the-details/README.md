# Hiding the Details

**Abstraction** means hiding the details you don't need right now. When you drive a car, you don't think about pistons firing, you just steer and press pedals.

Programmers do the same thing. They tuck complicated logic behind a simple name so they can focus on one level of the problem at a time.

## True or False

**1. True or false:** Abstraction means you must understand every internal detail before you can use something.

<details>
<summary>Answer</summary>

**False**: Abstraction is the opposite, it means hiding details you don't need. You can drive a car without understanding how the pistons work, just as programmers use tools without knowing every internal mechanism.

</details>

**2. True or false:** When a programmer names a complex piece of logic 'send_email,' they are using abstraction.

<details>
<summary>Answer</summary>

**True**: By tucking the complicated steps of sending an email behind a simple name, the programmer hides the details. Anyone using 'send_email' doesn't need to know how it works internally.

</details>

**3. True or false:** Abstraction makes programs harder to understand because it removes information.

<details>
<summary>Answer</summary>

**False**: Abstraction actually makes programs easier to understand. By hiding unnecessary details behind simple names, programmers can focus on the big picture without getting lost in complexity.

</details>
