# Functional Requirements

A **functional requirement** specifies what a system should do. It defines tasks, features, and functions the system must perform to satisfy user needs.

> [!note]
> Functional requirements focus on "what" the system does, not "how" it does it. 

Examples include user authentication, data processing, and report generation. Each requirement must be clear and testable to ensure correct implementation.

## Quiz

**1. What is the main focus of functional requirements?**

- A) How the system operates internally
- B) What the system should do
- C) The design aesthetics of the system
- D) The financial cost of system development

<details>
<summary>Answer</summary>

- B) What the system should do

Functional requirements focus on 'what' the system must do to meet user needs, not 'how' it is implemented.

</details>

**2. Which of the following is an example of a functional requirement?**

- A) The system must be secure against data breaches
- B) Users must be able to reset their passwords
- C) The interface should be user-friendly
- D) Data processing should use less than 2GB of RAM

<details>
<summary>Answer</summary>

- B) Users must be able to reset their passwords

A requirement that specifies an action the system must perform, such as password reset capability, is a functional requirement.

</details>

**3. Why must functional requirements be clear and testable?**

- A) To enhance system security
- B) To ensure they are implemented correctly
- C) To reduce the cost of system development
- D) To increase the speed of system operation

<details>
<summary>Answer</summary>

- B) To ensure they are implemented correctly

Clear and testable functional requirements facilitate correct implementation by providing specific criteria for what the system must do.

</details>
