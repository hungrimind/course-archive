# Understanding Alerts

A **alert** is a notification triggered when a system metric or log event meets predefined conditions. Alerts help promptly detect and address issues.

```plaintext
Example: CPU usage exceeds 80% for 5 minutes
```

> [!warning]
> Over-alerting can lead to alert fatigue, where critical alerts get ignored. Set thresholds carefully.

## Quiz

**1. What is the primary purpose of an alert in a monitoring system?**

- A) To maintain a detailed log history.
- B) To notify when specific conditions are met.
- C) To regularly update system software.
- D) To automate system backup processes.

<details>
<summary>Answer</summary>

- B) To notify when specific conditions are met.

An alert is designed to notify system administrators or support teams when predefined conditions are met, allowing them to promptly address potential issues.

</details>

**2. Why is it important to set thresholds carefully for alerts?**

- A) To increase the number of notifications for all events.
- B) To reduce the necessity for system monitoring.
- C) To prevent alert fatigue by avoiding unnecessary notifications.
- D) To ensure all system data is permanently stored.

<details>
<summary>Answer</summary>

- C) To prevent alert fatigue by avoiding unnecessary notifications.

Carefully set thresholds help prevent alert fatigue, where too many notifications can lead to critical alerts being overlooked.

</details>

**3. What could be a practical example of a condition that triggers an alert?**

- A) The system backup occurs successfully.
- B) File creation by any user.
- C) CPU usage exceeds 80% for 5 minutes.
- D) A user logs in at any time of the day.

<details>
<summary>Answer</summary>

- C) CPU usage exceeds 80% for 5 minutes.

A practical example of a condition that triggers an alert is CPU usage exceeding 80% for a continual duration, indicating potential system strain.

</details>
