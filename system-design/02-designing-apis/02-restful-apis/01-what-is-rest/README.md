# What is REST?

A **REST** (Representational State Transfer) is an architectural style for designing networked applications. It relies on stateless, client-server communication, primarily using HTTP.

> [!note]
> REST is not a protocol but a set of guidelines for scalable web services.

RESTful systems use resources, represented by URLs, which can be manipulated using standard HTTP methods like GET, POST, PUT, and DELETE. This approach allows different clients to interact with servers in a uniform way, promoting scalability and simplicity.

## True or False

**1. True or false:** REST is a protocol that mandates how web services should be structured.

<details>
<summary>Answer</summary>

**False**: REST is not a protocol, but an architectural style that provides guidelines for creating scalable web services.

</details>

**2. True or false:** RESTful systems use HTTP methods such as GET, POST, PUT, and DELETE to manipulate resources.

<details>
<summary>Answer</summary>

**True**: RESTful systems utilize standard HTTP methods to perform operations on resources represented by URLs, allowing for uniform interaction.

</details>

**3. True or false:** In a REST architecture, the communication between the client and server must be stateful.

<details>
<summary>Answer</summary>

**False**: REST relies on stateless communication, meaning each request from the client contains all the information needed to process it, without relying on stored context on the server.

</details>

**4. True or false:** A key advantage of REST is that it promotes scalability and simplicity in networked applications.

<details>
<summary>Answer</summary>

**True**: By using a stateless client-server architecture and standard HTTP methods, REST promotes scalability and simplicity through uniform interfaces and reduced server workload.

</details>
