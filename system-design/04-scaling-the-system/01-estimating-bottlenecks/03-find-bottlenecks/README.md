# Find Bottlenecks

To **find bottlenecks** in a system, identify components where performance degrades as load increases. Bottlenecks can occur in the CPU, memory, network, or disk I/O.

Use these steps: 

1. **Monitor Metrics**: Track CPU usage, memory, I/O, and network latency.
2. **Analyze Logs**: Look for patterns indicating slowdowns, such as long response times.
3. **Conduct Load Testing**: Simulate high traffic to see where the system struggles.

> [!note]
> Bottlenecks often shift as systems scale, so continual monitoring and testing are essential.

## True or False

**1. True or false:** Bottlenecks in a system only occur with the CPU.

<details>
<summary>Answer</summary>

**False**: Bottlenecks can occur in the CPU, memory, network, or disk I/O, not just the CPU.

</details>

**2. True or false:** Monitoring metrics is a crucial step in identifying system bottlenecks.

<details>
<summary>Answer</summary>

**True**: Monitoring metrics like CPU usage, memory, I/O, and network latency helps detect performance issues in different system components.

</details>

**3. True or false:** Bottlenecks remain constant as the system scales.

<details>
<summary>Answer</summary>

**False**: Bottlenecks often shift as systems scale, necessitating continual monitoring and load testing.

</details>

**4. True or false:** Load testing is used to simulate high traffic conditions to identify system bottlenecks.

<details>
<summary>Answer</summary>

**True**: Load testing helps reveal where the system struggles under high traffic, making it an effective tool for identifying bottlenecks.

</details>
