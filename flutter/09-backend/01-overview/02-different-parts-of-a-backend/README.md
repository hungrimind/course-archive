# Different Parts of a Backend

## The Flutter App Restaurant

Imagine your Flutter app is like a restaurant:

- Your Flutter UI (widgets, screens, animations) is like the dining area and waiters
- The backend is like the kitchen and storage areas

Just as a waiter (your Flutter app) takes orders from customers (your users) and brings back food from the kitchen (backend), your app sends requests to a backend and displays the returned data to users.

## Why Does Your Flutter App Need a Backend?

1. **Data Persistence**: When users close your app, their data needs to live somewhere
2. **Shared Data**: Multiple users need to access the same information
3. **Security**: Sensitive operations (like payments) need to happen in a secure environment
4. **Heavy Processing**: Some tasks are too intensive for mobile devices (like LLMs)

Again, this term "backend" can be anything that is outside of your app, but still used in some way by that app.

The most common examples that we will cover are:

- Authentication
- Database
- APIs

## Quiz

**1. What part of a Flutter App Restaurant is the backend?**

- A) The kitchen
- B) The dining area
- C) The waiters
- D) The customers

<details>
<summary>Answer</summary>

- A) The kitchen

</details>

**2. Which of the following does not need to be done on a backend?**

- A) Storing user data
- B) Handling heavy processing like LLMs
- C) Displaying data to the user
- D) Authenticating users

<details>
<summary>Answer</summary>

- C) Displaying data to the user

</details>
