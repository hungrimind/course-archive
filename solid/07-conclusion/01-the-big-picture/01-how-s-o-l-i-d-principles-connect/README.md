# How S.O.L.I.D Principles Connect

The **S.O.L.I.D principles** are interconnected guidelines that collectively enhance software design in object-oriented programming. Each principle addresses a specific aspect of design, but together they create a cohesive approach to building robust and maintainable systems.

- **Single Responsibility Principle (SRP)** ensures that a class has one reason to change, reducing complexity.
- **Open/Closed Principle (OCP)** allows systems to grow without altering existing code, promoting flexibility.
- **Liskov Substitution Principle (LSP)** ensures that derived classes can replace base classes without altering functionality, maintaining integrity.
- **Interface Segregation Principle (ISP)** prevents clients from being forced to depend on unused methods, enhancing usability.
- **Dependency Inversion Principle (DIP)** shifts focus from concrete implementations to abstractions, improving adaptability.

> [!note]
> Together, these principles reduce code fragility and complexity, making software easier to understand, extend, and refactor.
