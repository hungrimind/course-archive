# Making Better Architectural Decisions

S.O.L.I.D principles are key guidelines in object-oriented programming that improve code quality. They make software **maintainable**, **scalable**, and **readable** by addressing common design challenges.

Each principle, from Single Responsibility to Dependency Inversion, promotes a cohesive code structure. 

**Don't worry we will cover all of them.**

They are essential for making informed architectural decisions. Just remember to apply them where they make sense rather than following them dogmatically.

## Quiz

**1. What is the primary benefit of applying S.O.L.I.D principles in object-oriented programming?**

- A) They improve code security.
- B) They make software maintainable, scalable, and readable.
- C) They enhance code compilation speed.
- D) They ensure adherence to the latest programming paradigms.

<details>
<summary>Answer</summary>

- B) They make software maintainable, scalable, and readable.

</details>

**2. What's a key consideration when applying S.O.L.I.D principles?**

- A) Apply them to every piece of code without exception.
- B) Apply them dogmatically, regardless of context.
- C) Apply them where they make sense, and not dogmatically.
- D) Avoid them unless you are working on a large-scale project.

<details>
<summary>Answer</summary>

- C) Apply them where they make sense, and not dogmatically.

</details>

**3. Which aspect of software is NOT directly addressed by S.O.L.I.D principles?**

- A) Code scalability
- B) Code readability
- C) Code maintainability
- D) Code execution speed

<details>
<summary>Answer</summary>

- D) Code execution speed

</details>
